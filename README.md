# agent_nirs — LLM, инструменты, харнесс и MCP на Go

Пять программ, которые по шагам показывают, чем отличаются:

1. **LLM + инструменты** (без харнесса);
2. **LLM + харнесс** (без инструментов);
3. **LLM + харнесс + локальные инструменты**;
4. **LLM + харнесс + инструменты по MCP** (вместе с локальными);
5. **LLM + харнесс + субагенты** (главный агент передаёт часть работы другим агентам).

Код написан только на стандартной библиотеке Go. Пакеты и типы названы по
терминам из глоссария НИРС, а в doc-комментариях пакетов приведены
определения из глоссария (с пояснениями, как они отражены в коде).

## Быстрый запуск на своём компьютере

1. Установите [Go 1.22 или новее](https://go.dev/dl/) и [Git](https://git-scm.com/downloads).
   Проверьте в терминале: `go version` и `git --version`.
2. Создайте ключ в [OpenRouter → Keys](https://openrouter.ai/settings/keys).
   Выберите [модель с поддержкой tools](https://openrouter.ai/models?supported_parameters=tools&max_price=0).
3. Выполните команды ниже для своего терминала. Вместо `ВАШ_КЛЮЧ_OPENROUTER`
   укажите свой ключ; `LLM_MODEL` — идентификатор выбранной модели.
   В примере указана бесплатная модель, но её доступность может меняться.

**Linux / macOS (bash или zsh):**

```bash
git clone https://github.com/wannacry39/agent_nirs.git
cd agent_nirs

export LLM_BASE_URL="https://openrouter.ai/api/v1"
export LLM_API_KEY="ВАШ_КЛЮЧ_OPENROUTER"
export LLM_MODEL="nvidia/nemotron-3.5-super-vl:free"

go run ./cmd/03_harness_local_tools "Какая погода в Казани?"
```

**Windows (PowerShell):**

```powershell
git clone https://github.com/wannacry39/agent_nirs.git
cd agent_nirs

$env:LLM_BASE_URL="https://openrouter.ai/api/v1"
$env:LLM_API_KEY="ВАШ_КЛЮЧ_OPENROUTER"
$env:LLM_MODEL="nvidia/nemotron-3.5-super-vl:free"

go run ./cmd/03_harness_local_tools "Какая погода в Казани?"
```

Этот пример запускает агента с харнессом и локальными инструментами:
модель может предложить вызов инструмента погоды; тогда харнесс выполняет
его и возвращает результат модели. Данные погоды учебные, выдуманные.
Ход работы выводится в терминал, затем появляется ответ.

Для диалога запустите в том же терминале `go run ./cmd/03_harness_local_tools`
без аргументов. Пустая строка завершает диалог.

Все команды `go run` выполняйте из корня `agent_nirs`. Внешних Go-зависимостей
нет: отдельно устанавливать пакеты не нужно. Переменные действуют в текущем
терминале; в новом их нужно задать заново. `.env.example` — только образец:
программа **не загружает `.env` автоматически**.

**Чтобы попробовать MCP (вариант 4):** оставьте терминал с настроенными
переменными для агента. Откройте второй терминал, перейдите в корень
`agent_nirs` и запустите сервер:

```bash
go run ./cmd/mcp_mail_server
```

После сообщения о запуске сервера вернитесь в первый терминал:

```bash
go run ./cmd/04_harness_mcp_tools "Есть письма от начальника?"
```

Сервер должен оставаться запущенным. Адрес по умолчанию —
`http://127.0.0.1:8000/mcp`; почта также учебная, реальный почтовый ящик
подключать не нужно. Другие варианты и провайдеры описаны в разделе [«Запуск»](#запуск).

## Контроль исходящих данных

Модуль `internal/egress` проверяет данные перед отправкой внешней LLM или
MCP-сервису. Харнесс применяет политику; модель продолжает только предлагать
действия. Проверка работает локально, не вызывает внешнюю LLM и не подменяет
аргументы. Первая версия разрешает или блокирует передачу.

Попробовать без ключей и внешних сервисов:

```bash
go run ./cmd/egress_demo
```

Для включения в примерах с харнессом настройте OpenRouter по инструкции выше,
затем задайте путь политики:

```bash
export AGENT_EGRESS_POLICY=config/egress.example.json
go run ./cmd/03_harness_local_tools "Какая погода в Казани?"
```

В PowerShell: `$env:AGENT_EGRESS_POLICY="config/egress.example.json"`.
Та же настройка действует для вариантов 02 и 04. Ключ `LLM_API_KEY`
автоматически защищается во всех каналах; дополнительные секреты можно
объявить в `secret_env` политики, указав только имена переменных.

**Без этой переменной исходящие данные не фильтруются.** Если политика указана,
но некорректна, запуск останавливается. Вариант 01 не подключает харнесс и
отклоняет запуск с этой настройкой. Пример политики разрешает email только
в поле поиска учебного MCP, а отправку email в контексте OpenRouter блокирует.

Детекторы покрывают известные секреты, выбранные форматы токенов, чувствительные
поля, email и телефоны поддерживаемых форматов. Это учебный контроль с явными
ограничениями; новые сетевые обработчики должны использовать защищённые клиенты.
Проверки: `go vet ./...` и `go test -race ./...`.

Подробности: [настройка, архитектура, ограничения и тесты](docs/egress-security.md).

## Чем отличаются варианты

| | 1. LLM + инструменты | 2. LLM + харнесс | 3. + локальные инструменты | 4. + MCP-инструменты | 5. + субагенты |
|---|---|---|---|---|---|
| Модель получает описания инструментов | да | нет | да | да | да, в том числе `run_subagent` |
| Кто выполняет вызов инструмента | **никто** | — | харнесс, внутри программы | локальные — харнесс; MCP — MCP-сервер (харнесс отправляет вызов через MCP-клиент) | как в 4; `run_subagent` выполняет харнесс: собирает и запускает харнесс субагента |
| Цикл агента (LLM → шаг → результат → LLM) | нет, один вызов | есть, но всегда 1 шаг — ответ | есть | есть | есть; у каждого субагента свой цикл |
| История между запросами | нет (LLM stateless) | да | да | да | да у главного агента; у субагента нет |
| Релевантные данные из памяти в контексте | нет | да | да | да | да у главного агента; субагент получает только task |
| Skills (каталог + `load_skill`) | нет | нет | да | да | да, у каждого агента свои |
| Проверка запроса на валидность и безопасность | нет | да | да | да | да; task субагента проверяется так же |
| Лимиты, сжатие контекста | нет | да | да | да | да, у субагента свои лимиты |
| Подтверждение опасных вызовов | нет | — | да (`save_note`) | да (`save_note`, `delete_message`) | да, вызовы субагента с пометкой «[субагент …]» |

Системный промпт собирается `prompt.Build` под возможности варианта: в
варианте 2 нет разделов про инструменты и skills, в варианте 1 — про skills.
Внутри одного запуска он не меняется.

Главное:

- **1 → 2.** Сама LLM ничего не выполняет и ничего не помнит. Она лишь
  возвращает текст или вызов инструмента (имя и параметры). В варианте 1 видно,
  что вызов просто печатается: исполнить его некому. Харнесс в варианте 2
  добавляет историю, память, проверки и лимиты, но без инструментов модели
  доступен только один шаг — финальный ответ. Формально это вырожденный агент.
- **2 → 3.** Харнесс получает инструменты, и цикл агента становится полным:
  модель предлагает вызов, харнесс проверяет и выполняет его, кладёт результат
  в контекст и снова вызывает модель. Вместе с инструментами появляются:
  - skills — тоже через инструмент: встроенный инструмент харнесса `load_skill`;
  - подтверждение опасного вызова (`save_note` меняет данные пользователя).
- **3 → 4.** Код харнесса не меняется. Добавляется ещё один источник
  инструментов, MCP-клиент (`mcp.Client` реализует тот же интерфейс
  `tools.Toolbox`, что и `LocalToolbox`). Модель видит одинаковые описания
  и не может отличить локальный инструмент от MCP-инструмента. Где
  выполнять вызов, решает харнесс.

- **4 → 5.** Код харнесса снова не меняется. Набор субагентов
  (`subagent.Toolbox`) реализует тот же `tools.Toolbox`, и модель главного
  агента видит ещё один инструмент, `run_subagent(agent, task)`. Харнесс на
  каждый вызов собирает **новый харнесс**: свой цикл, пустой контекст, свой
  системный промпт, свои инструменты, skills и лимиты. Главному агенту
  возвращается только итог. Субагент не особый вид агента, а роль: внутри
  это тот же `harness.Harness`. Главный агент и субагент могут ходить к
  одному и тому же инструменту одного MCP-сервера: один `mcp.Client`
  лежит в источниках инструментов обоих харнессов.

Как это выглядит в логах (заглушка вместо LLM):

```
# Вариант 1 — вызов есть, выполнить его некому
Модель вернула вызов инструмента: get_weather {"city": "Казань"}
На этом всё. LLM только предложила вызвать инструмент.

# Вариант 3 — харнесс выполняет локальный инструмент сам
[LLM] шаг 1: предлагает вызвать load_skill({"name": "weather_report"})
[харнесс] записал в контекст skill "weather_report"
[LLM] шаг 2: предлагает вызвать get_weather({"city": "Казань"})
[харнесс] выполняю get_weather (локально)
[LLM] шаг 3: ответ текстом, цикл завершён

# Вариант 4 — тот же цикл, но вызов уходит на MCP-сервер
[LLM] шаг 2: предлагает вызвать search_messages({"query": "boss@company.com"})
[харнесс] выполняю search_messages (MCP-сервер http://127.0.0.1:8000/mcp)
[MCP-сервер] tools/call: выполняю search_messages map[query:boss@company.com]

# Вариант 5 — главный агент передаёт задачу субагенту
[LLM] шаг 1: предлагает вызвать run_subagent({"agent": "weather", "task": "Сводка погоды по городу Казань"})
[харнесс] запускаю субагента weather: свой цикл, пустой контекст
    [субагент weather] [LLM] шаг 1: предлагает вызвать load_skill({"name": "weather_report"})
    [субагент weather] [LLM] шаг 2: предлагает вызвать get_weather({"city": "Казань"})
    [субагент weather] [LLM] шаг 3: ответ текстом, цикл завершён
[харнесс] субагент weather вернул итог, его промежуточные шаги в контекст не попадают
```

## Как устроено (термины → код)

| Термин | Где в коде |
|---|---|
| LLM | `internal/llm`: один вызов `Complete(messages, tools)`, состояния нет |
| Токен | `llm.Response.TotalTokens`, лимит `Limits.MaxTokens` |
| Запрос пользователя | аргумент `harness.Run(request)` |
| Системный промпт, критерии завершения | `internal/prompt`: собирается один раз при запуске и дальше не меняется |
| Промпт-инъекция | `harness.checkSecurity` (запрос), предупреждение в `harness.execute` (результаты инструментов) |
| Инструмент (name, description, input_schema, required) | `tools.Tool` (`required` лежит внутри `InputSchema`, как в JSON Schema) |
| Список инструментов | `agentcontext.Context.Tools`, собирается харнессом из всех `Toolbox` |
| Вызов инструмента | `llm.ToolCall`: модель возвращает имя и параметры |
| Результат инструмента | `tools.Result`: данные или ошибка (`IsError`, в контекст идёт с пометкой «Ошибка:») |
| Шаг | вызов инструмента или финальный ответ; считается в `harness.Run` |
| Локальный инструмент | `tools.LocalToolbox`, `internal/localtools` |
| Транспорт | `mcp.Transport`, реализация `mcp.HTTPTransport` |
| JSON-RPC 2.0 | `mcp.Request`, `mcp.Response` в `internal/mcp/protocol.go` |
| MCP | `internal/mcp`: `initialize`, `tools/list`, `tools/call` поверх JSON-RPC 2.0 и HTTP |
| MCP-сервер | `mcp.Server`, `cmd/mcp_mail_server` |
| MCP-клиент | `mcp.Client` |
| MCP-инструмент | инструменты, которые харнесс получает от `mcp.Client` |
| Постоянное хранилище | `memory.Storage`: файл `data/memory.json` |
| Память | `memory.Memory`; модель о ней не знает, обращается к ней только харнесс |
| Релевантные данные | `memory.Memory.Relevant`: передаются в контекст справочным блоком |
| RAG | `Relevant` — упрощённый RAG: поиск по совпадению слов вместо эмбеддингов |
| Skill | `internal/skills`, папка `skills/`: в контексте каталог, текст записывается в контекст по выбору модели (`load_skill`) |
| Контекст | `internal/agentcontext`: системный промпт, инструменты, каталог и тексты skills, релевантные данные, краткое содержание, история |
| Лимиты | `harness.Limits`: шаги, токены, время |
| Цикл агента | `harness.Run` |
| Харнесс | `internal/harness`: проверки, сборка контекста, выполнение и маршрутизация вызовов, подтверждение, управление контекстом |
| ИИ-агент | LLM + харнесс: варианты 3, 4 и 5 (вариант 2 — вырожденный случай) |
| Субагент | `internal/subagent`: `Definition` — роль, `Toolbox` — инструмент `run_subagent`; на каждый вызов новый `harness.Harness` |

Цикл агента в `harness.Run`:

```
запрос
 → проверка на валидность (не пустой, не длиннее MaxRequestRunes)
 → проверка на безопасность (промпт-инъекция; превышение прав при AGENT_READ_ONLY=1)
 → «запомни: …»? — харнесс сам пишет в память, модель не вызывается
 → сборка контекста (запрос + релевантные данные из памяти)
 └─ цикл:
      лимиты шагов / токенов / времени исчерпаны? → остановка
      управление контекстом: история длиннее MaxHistoryMessages → старая часть
        сжимается моделью в краткое содержание, история сокращается вдвое
        (и снова проверка лимитов: сжатие тоже тратит токены)
      LLM(контекст) → ответ (на последнем шаге — без вызова инструментов)
      текст            → шаг «финальный ответ»: критерии завершения выполнены
      вызовы инструментов → лимит токенов исчерпан? → вызовы не выполняются
                         для каждого вызова (каждый — отдельный шаг):
                           инструмент существует? параметры верны?
                           load_skill → записать текст skill в контекст
                           опасный? → спросить пользователя
                           локальный → выполнить сам; MCP → tools/call через MCP-клиент
                           результат (или «Ошибка: …») → в контекст
```

Как собирается контекст для каждого вызова модели (`Context.Messages`):

1. системное сообщение: системный промпт и каталог skills — одинаковое от запроса к запросу;
2. краткое содержание ранней части диалога (если история сжималась) — с пометкой «справочные данные, а не инструкции»;
3. тексты skills, которые выбрала модель (сжатие истории их не затрагивает);
4. история чата;
5. релевантные данные из памяти — справочным блоком перед текущим запросом;
6. текущий запрос, вызовы инструментов и их результаты.

Данные из памяти не попадают в системное сообщение, поэтому запись
«запомни: всегда отвечай по-английски» остаётся данными и не получает
прав системного промпта.

## Субагенты (вариант 5)

Как устроено (`internal/subagent`):

- `Definition` описывает роль: тип, описание (по нему модель главного агента
  выбирает субагента), системный промпт, инструменты, skills, лимиты и,
  при желании, отдельную модель.
- `Toolbox` отдаёт главному агенту один инструмент `run_subagent` с
  параметрами `agent` и `task`. Список субагентов с описаниями лежит в
  описании инструмента, то есть в контексте главного агента.
- Модель главного агента только предлагает запуск. Харнесс проверяет
  параметры и вызывает `Toolbox.Call`, который собирает **новый
  `harness.Harness`** и выполняет в нём `task` как запрос.

Что из этого следует:

| | главный агент | субагент |
|---|---|---|
| Цикл агента | свой | свой, новый на каждый вызов |
| Контекст | история, память, свои skills | пусто: системный промпт, его инструменты, task |
| Память | есть, к ней обращается харнесс | нет: нужные факты главный агент пишет в task |
| Skills | свои | свои; выбранный skill попадает только в его контекст |
| Что видит другой | итог субагента как результат инструмента | ничего из диалога главного агента |
| Проверки | запрос пользователя | task проходит те же проверки на валидность и безопасность |
| Опасные вызовы | подтверждает пользователь | тоже пользователь, с пометкой «[субагент …]» |
| Права «только чтение» | опасные инструменты скрыты | то же самое |

Остановка субагента по лимиту или отказ в проверке возвращается главному
агенту как ошибка инструмента, а не как ответ. Субагенту можно дать другой
набор субагентов: вложенность получается сама, потому что `subagent.Toolbox`
это обычный `tools.Toolbox`.

**Общий инструмент.** В варианте 5 один и тот же `mcp.Client` почтового
сервера лежит в источниках инструментов и главного агента (через
`tools.Subset`, только `search_messages`), и субагента `mail` (все
инструменты почты). Для MCP-сервера это один клиент и одна сессия, вызовы
идут по очереди (субагент работает внутри `execute` главного агента). Так
главный агент делает короткую проверку сам, а объёмный разбор отдаёт
субагенту: полные тексты писем ложатся в контекст субагента, главный
получает одну строку итога. Промпт `prompt.Delegation()` это правило и
формулирует: один короткий вызов делай сам, объёмную работу передай.
Тест `TestSharedToolboxUsedByMainAndSubagent`: один источник, два вызова
(от главного и от субагента), в контексте главного только его вызов и итог.

Прогон (`nvidia/nemotron-3.5-super-vl:free`): главный агент сам ищет письма
начальника, а сводку всей почты отдаёт субагенту, который через тот же
MCP-клиент берёт все письма:

```
$ go run ./cmd/05_harness_subagents "Есть ли письма от начальника? И сделай сводку всей почты от коллег с адресов @company.com."
[MCP-клиент] подключён к http://127.0.0.1:8000/mcp, инструментов: 3
```

## Права и опасные действия

- Опасный инструмент (`save_note`, `delete_message`) выполняется только после подтверждения пользователя.
- До выполнения харнесс проверяет обязательные поля и типы параметров.
  MCP-сервер независимо делает ту же проверку: другой клиент тоже может
  прислать неправильные аргументы. Учебный валидатор поддерживает только
  `type`, `properties`, `required`, `items`, а не всю JSON Schema.
- У MCP-инструментов харнесс считает опасным всё, у чего нет аннотации `readOnlyHint: true`: так по умолчанию трактует инструменты спецификация MCP.
- `AGENT_READ_ONLY=1` — права «только чтение»:
  - действует во всех вариантах с харнессом, включая вариант 2 и запись памяти;
  - запрос на изменение данных (в том числе «запомни: …») отклоняется
    проверкой на безопасность ещё до цикла. Это эвристика: ищутся глаголы
    вроде «удали», «сохрани», «отправь»;
  - опасные инструменты не попадают в список инструментов модели. Это
    основная защита: даже если эвристика пропустит запрос, модели нечем
    изменить данные.

## Запуск

Нужен Go 1.22+ и любой OpenAI-совместимый API, который поддерживает вызов
инструментов (tools). Команды выполняются из корня репозитория.

**OpenRouter (бесплатно, рекомендуется для начала).** Открывается из России
без VPN, бесплатные модели (с суффиксом `:free`) работают без карты.

1. Зарегистрироваться на [openrouter.ai](https://openrouter.ai) и создать ключ
   в разделе [Keys](https://openrouter.ai/settings/keys).
2. Выбрать бесплатную модель с поддержкой инструментов:
   [список](https://openrouter.ai/models?supported_parameters=tools&max_price=0).
   Набор бесплатных моделей меняется; на октябрь 2026 подходит, например,
   `nvidia/nemotron-3.5-super-vl:free`.
3. Задать переменные (PowerShell):

```powershell
$env:LLM_BASE_URL="https://openrouter.ai/api/v1"
$env:LLM_API_KEY="sk-or-v1-..."
$env:LLM_MODEL="nvidia/nemotron-3.5-super-vl:free"
```

Ограничения бесплатного тарифа: 20 запросов в минуту и 50 в день. Один запрос
к агенту — это 2–4 вызова модели, то есть примерно 15–20 запросов к агенту в
день. При ответе 429 клиент сам повторяет запрос с паузой. Запросы к
бесплатным моделям провайдер может использовать для обучения — не отправляйте
личные данные.

**Ollama (локально, бесплатно).** Установить с [ollama.com](https://ollama.com), затем:

```bash
ollama pull qwen2.5:7b            # ~4.7 ГБ, нужно ~8 ГБ памяти; на слабой машине — qwen2.5:3b
export LLM_BASE_URL=http://localhost:11434/v1
export LLM_API_KEY=ollama         # любая строка
export LLM_MODEL=qwen2.5:7b
```

**Yandex AI Studio:**

```bash
export LLM_BASE_URL=https://llm.api.cloud.yandex.net/v1
export LLM_API_KEY=<API-ключ>
export LLM_PROJECT=<ID каталога>
export LLM_MODEL=gpt://<ID каталога>/yandexgpt/latest
```

**OpenAI:** `LLM_BASE_URL=https://api.openai.com/v1`, `LLM_API_KEY=sk-...`, `LLM_MODEL=gpt-4o-mini`.

В bash переменные задаются через `export LLM_MODEL=...`, в Windows PowerShell —
`$env:LLM_MODEL="..."`. Пример всех переменных — в `.env.example`.

Если модель не подходит, клиент подскажет, что не так: неверный ключ,
модель без поддержки инструментов, исчерпан лимит.

```bash
# 1. LLM + инструменты: модель вернёт вызов, но выполнять его некому
go run ./cmd/01_llm_tools "Какая погода в Казани?"

# 2. LLM + харнесс: диалог с историей и памятью, без инструментов
go run ./cmd/02_llm_harness
#   > запомни: я болею за Рубин
#   > За какую команду я болею?

# 3. LLM + харнесс + локальные инструменты
go run ./cmd/03_harness_local_tools
#   > Какая погода у меня в городе?   (город — из памяти, skill weather_report)
#   > Сохрани заметку: купить хлеб    (харнесс спросит подтверждение)
AGENT_READ_ONLY=1 go run ./cmd/03_harness_local_tools "Сохрани заметку: купить хлеб"   # отказ: превышение прав

# 4. LLM + харнесс + MCP-инструменты
go run ./cmd/mcp_mail_server            # отдельный терминал: MCP-сервер почты на :8000
go run ./cmd/04_harness_mcp_tools
#   > Есть письма от начальника?        (адрес начальника — из памяти, skill inbox_digest)
#   > Удали рекламное письмо            (харнесс спросит подтверждение)

# 5. LLM + харнесс + субагенты (субагент mail и search_messages у главного — если запущен MCP-сервер)
go run ./cmd/05_harness_subagents
#   > Какая погода у меня в городе и есть ли письма от начальника?
#     (город и адрес из памяти главный агент сам вписывает в задачи субагентам)

# Тесты: цикл агента, лимиты, права, контекст, MCP-клиент и сервер
go test ./...
```

Каждая программа пишет ход работы в stderr: строки `[LLM]` — что предложила
модель, `[харнесс]` — что сделал харнесс, `[MCP-сервер]` — что выполнил сервер.
Если передать запрос аргументами, он выполнится один раз; без аргументов
запускается диалог.

Память при первом запуске копируется из `data/memory.example.json` в
`data/memory.json` (этот файл и заметки `data/notes.txt` в git не хранятся).

## Замечания

- MCP реализован вручную (HTTP + JSON-RPC 2.0, подмножество транспорта
  Streamable HTTP), чтобы было видно, что это за протокол:
  - транспорт отделён от сообщений;
  - клиент переподключается, если сервер забыл сессию;
  - клиент проверяет версию MCP и наличие возможности `tools`;
  - при переподключении каталог инструментов сравнивается с исходным. Если
    поменялись имена, описания, схемы или признак опасного действия, вызовы
    блокируются до перезапуска агента: харнесс должен заново проверить права;
  - сервер проверяет `Origin`.

  Реализация совместима с официальным SDK: Go-клиент работает с сервером на
  Python SDK (`FastMCP`, ответы в SSE), а Python-клиент — с Go-сервером.
  В реальном проекте вместо `internal/mcp` стоит взять официальный
  [github.com/modelcontextprotocol/go-sdk](https://github.com/modelcontextprotocol/go-sdk).
  SDK предоставляет готовые MCP-клиент, сервер и транспорты. Харнесс,
  его проверки прав, память и цикл агента при этом остаются кодом приложения;
  адаптер SDK может реализовать тот же `tools.Toolbox`.
- Релевантные данные ищутся по совпадению слов. Это упрощённый RAG: обычно
  ищут по эмбеддингам, то есть по смыслу.
- Проверки на безопасность упрощены: промпт-инъекция ищется регулярным
  выражением, права — один флаг «только чтение». Они показывают, в каком
  месте цикла стоят проверки.
- Стоимость отдельно не ограничивается: она пропорциональна токенам, поэтому
  её ограничивает лимит токенов. Если провайдер не сообщает расход токенов,
  он оценивается по объёму запроса и ответа.
- Справочные блоки и тексты skills передаются отдельными сообщениями с ролью
  `user`, поэтому несколько таких сообщений могут идти подряд. OpenAI, Ollama
  и большинство моделей это принимают. Шаблоны со строгим чередованием ролей
  (например, некоторые модели Mistral в vLLM) могут вернуть ошибку.
- Если остался последний шаг, харнесс просит модель ответить без вызова
  инструментов (`tool_choice: none`), чтобы работа не закончилась без ответа.
  Это действует и при нескольких вызовах в одном ответе: лишние вызовы
  помечаются как невыполненные, а последний шаг используется для ответа.
  Если модель игнорирует запрет на инструменты, цикл останавливается.
- Сжатие истории использует оставшееся время запроса. При пустой или
  оборванной сводке история сохраняется и возвращается ошибка.
- Ответ с `finish_reason: length` отмечается как оборванный, даже если
  модель успела вернуть часть текста.
- Данные погоды и почты выдуманные.
