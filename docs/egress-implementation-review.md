## Соответствие архитектуре и определениям

| Граница | Проверенный результат |
| --- | --- |
| LLM и API-клиент | Модель по-прежнему генерирует текст/ToolCall. Программный клиент вызывает Guard перед отправкой; это не меняет определение LLM. |
| Харнесс | Проверяет передачу перед исполнением и подтверждением, сохраняет исходные аргументы и результат ошибки с ToolCallID. |
| Ядро egress | Зависит от стандартной библиотеки, не выполняет инструменты, не хранит историю/память и не вызывает внешнюю LLM. |
| Тулинг | Destination — служебные метаданные приложения; Tool.Spec не передаёт их модели. |
| MCP | Клиент продолжает отправлять JSON-RPC; сервер исполняет инструменты. DLP не перенесён в HTTPTransport. |
| Память/контекст | Исходная память не переписывается. Проверяется собранный исходящий контекст, включая запрос сжатия истории. |
| Системный промпт | Не подменяется для обхода запрета; модель получает прежнюю структуру сообщений. |
| Skills | load_skill получает внутреннее назначение в Harness.New, выполняется без h.route и остаётся внутри контекста своего харнесса. |
| Шаги/лимиты | Guard не добавляет шаг и вызов LLM. Отказ остаётся результатом выбранного вызова. Временной контекст передаётся проверке. |
| Четыре программы | Вариант 01 явно не подключает защиту; варианты с харнессом включают её через политику. Новый модуль не объявлен отдельным агентом/skill. |

### Три исходных замечания плана

1. **load_skill — закрыто в коде.** Служебное назначение
   `egress.SkillDestination()` задаётся при создании инструмента; обязательное
   правило проверяется при сборке. Локальная загрузка и внешняя передача
   загруженного текста контролируются отдельно.
2. **Канонические операции/пути — закрыто в коде.** `ToolAttempt` используется
   харнессом и MCP-адаптером. Метод `tools/call` разбирается в имя инструмента
   и корень arguments; лишние поля оболочки не наследуют разрешение для query.
   Запрос внешней LLM остаётся отдельной `ModelOperation`.
3. **Схемы и значения — закрыто в проверенных формах.** Только доверенный
   адаптер маркирует `ToolSpec.function.parameters` как Schema. Декларация
   password не равна его значению; default/examples и описания проверяются.
   `kind: "schema"` в JSON-аргументах такого исключения не создаёт.

## Находки, исправленные в ходе ревью

### 1. Учётный ключ модели защищался не во всех каналах

Первоначально `c.APIKey` передавался детектору только из адаптера LLM. Если
политика явно не включала LLM_API_KEY в secret_env, ключ произвольного формата
мог быть отправлен как обычный аргумент MCP-инструмента.

Исправление: общий неизменяемый реестр `Options.Credentials` в Guard; CLI
регистрирует текущий LLM_API_KEY; `Harness.New` отклоняет сборку без регистрации
ключа модели. Категория credential не разрешается обычным исключением secret.
В MCP-тест добавлен нестандартный ключ без известного префикса.

Статус: закрыто статической проверкой сборки и независимым запуском теста
`TestEgressMCPDirectCanonicalCallsAndRetries`.

### 2. Числовые значения обходили строковые детекторы

Первоначальная ветка float64 проверяла только NaN/Inf. Известный секрет,
credential и телефон можно было передать JSON-числом в нейтральном поле.
Позднее обнаружено, что нормализация дроби через float64 теряет точные цифры:
credential `1234569990.123456999` не обнаруживался в эквивалентном
`1.234569990123456999e9`.

Исправление: сохранение json.Number, анализ исходной лексемы и ограниченной
точной десятичной записи, включая scientific notation. Для дробей используется
точная рациональная арифметика с ограничениями размера, вместо округления
перед сравнением. Поддержана проверка float64 для программных вызовов Guard.

Статус: закрыто; независимые `TestReviewNumericSensitiveValues` и
`TestReviewFractionalKnownCredential` прошли после исправлений. В основной
реализации также добавлены регрессионные тесты.

### 3. Присваивание с quoted key пропускалось

Строка вида `"password":"unknown-secret-value"` внутри обычного текстового
аргумента не распознавалась из-за кавычки между именем и двоеточием.

Исправление: правило текстового присваивания поддерживает согласованную
закрывающую кавычку у имени поля, без бесконечного декодирования произвольных
строк и без превращения JSON Schema в набор значений паролей.

Статус: закрыто; независимый `TestReviewQuotedTextAssignment` прошёл.

### 4. Boolean/null пропускали совпадение зарегистрированного credential

Options.Credentials допускает короткие значения. Зарегистрированные `true`,
`false`, `null` первоначально обходили сканирование как соответствующие
JSON-литералы.

Исправление: канонические представления boolean/null проходят проверку
известных значений; boolean-схема также не исключается из проверки строкового
совпадения. Это не запрет всех boolean/null, а проверка фактического совпадения
с зарегистрированным ключом.

Статус: закрыто; независимый `TestReviewLiteralCredentials` прошёл.

## Оставшиеся границы подтверждения

Сохраняются заявленные ограничения первой версии: детекторы имеют конечный
набор форматов, произвольное кодирование/разбиение секретов и недоверенный
исполняемый код не покрыты. Guard не заменяет сетевую песочницу. Прежние
ограничения токенового бюджета и учебной эвристики промпт-инъекций не считаются
устранёнными этой работой.

Конфигурация, demo и документация дорабатывались параллельно родительским
агентом. Их окончательный согласованный запуск и содержимое коммита требуется
проверить после стабилизации рабочего дерева. Этот отчёт не утверждает,
что какие-либо изменения уже опубликованы на GitHub.
